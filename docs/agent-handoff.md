# Handoff для агентов

Что нужно знать, прежде чем править этот проект. Здесь только то, что **не
выводится из чтения кода**: договорённости, ловушки, на которых уже теряли
время, и текущее состояние работ. Порядок работы с submodule —
[development-workflow.md](development-workflow.md), конвенции —
`tourism-platform/docs/development-conventions.md`.

Файл зеркалится на GitHub вместе с суперпроектом, поэтому **адресов серверов,
ключей и внутренних ссылок здесь нет**. Всё это — в
`tourism-platform/docs/ci-and-runners.md` (лежит только локально: в
`tourism-platform` весь `docs/*` в gitignore).

## Из чего состоит репозиторий

Суперпроект с тремя submodule:

| Модуль | Что это | Стек |
| --- | --- | --- |
| `tourism-backend` | API, админка, ИИ-подбор, RAG | FastAPI, SQLAlchemy, Alembic, PostGIS, Redis |
| `tourism-mobile` | приложение | Flutter, Riverpod |
| `tourism-platform` | документы, планы, решения | markdown, **не публикуется** |

Изменения коммитятся в дочерний репозиторий, потом в суперпроекте обновляется
SHA submodule отдельным коммитом `chore: bump <repo> to <sha>`.

## Договорённости с владельцем проекта

- **Сообщения коммитов — по-английски**, документы и история изменений — по-русски.
- **Деплой запускает владелец руками.** Job `backend-deploy-production` в GitLab
  ручной; агент его не триггерит, даже когда правка «очевидно готова». Сборку
  мобильного приложения владелец тоже делает сам.
- Правки на проде через SSH допустимы для файлов, которых нет в git
  (`deploy-remote.sh`, `compose.yaml` на сервере), но о них нужно сказать вслух —
  их не подхватит ни один MR.
- Прежде чем удалять данные на проде — показать, что именно удаляется, построчно
  с владельцем и содержимым. Однажды по совпадению имён были снесены реальные
  маршруты пользователя.

## Проверка перед коммитом

```bash
# backend
cd tourism-backend
uv run ruff check src tests && uv run ruff format --check src tests
uv run mypy src/tourism_backend
uv run pytest tests/unit -q --no-cov

# mobile
cd tourism-mobile
flutter analyze
flutter test
```

**7 упавших тестов и ~40 ошибок в `tests/unit` — это норма без локальной базы**
(они ходят в PostGIS). Сверяйтесь с чистым деревом (`git stash`), прежде чем
чинить «сломанное». Полный прогон бэкенда с базой — `./scripts/validate.sh`.

Пиксельные golden-тесты идут **только на macOS** (`_skipPixelGoldens`), там же и
перегенерируются: `flutter test --update-goldens --plain-name "<имя>"`.

## Ловушки, на которых уже теряли время

**Flutter-тесты считают платформу Android.** `defaultTargetPlatform` в
`flutter_test` прибит к Android, и `ThemeData(platform: iOS)` его не меняет. Код,
который ветвится через `AppPerf`, в тестах пойдёт по андроидной ветке, а тест
будет «зелёным», ничего не проверив. Нужен
`debugDefaultTargetPlatformOverride`, и сбрасывать его — в `try/finally` внутри
теста: `addTearDown` отрабатывает **после** проверки биндинга и падает с «foundation
debug variable was changed».

**`CustomPaint` поверх интерактивного слоя съедает нажатия.** Декоративный
оверлей во весь `Stack` (подсветка пройденного маршрута) отбирал тапы у карты под
ним. Такой слой всегда заворачивать в `IgnorePointer`.

**`tester.tap` не воспроизводит гонки внутри жеста.** Он шлёт down и up без кадра
между ними, поэтому баг «виджет исчез между нажатием и отпусканием» тест не
поймает. Нужен `startGesture` → `pump(80ms)` → `up()`. Так был найден баг с
историей поиска: снятие фокуса перестраивало дерево и уносило строку до того,
как срабатывал `onTap`.

**Finder'ы пропускают offstage.** После `Navigator.push` предыдущий экран
остаётся смонтированным, но `find.*` его не видит (`skipOffstage: true`), а
`find.bySemanticsLabel` работает по дереву семантики и не найдёт узел, обрезанный
`ClipRect`. Если проверяете конкретный экран — сужайте поиск через
`find.descendant`.

**Переменные окружения заводятся в двух местах.** Мало добавить переменную в
GitLab: её нужно вписать и в `scripts/ci-deploy-production.sh`, и в серверный
`deploy-remote.sh` (его в git нет). Плюс значение из `.env` **не попадает** в
контейнер, пока не указано в блоке `environment:` в `compose.yaml` на сервере.
Подробности и список — в `ci-and-runners.md`.

**История изменений проверяется тестами.** `lib/features/settings/domain/changelog.dart`
живёт в приложении, а не приходит с сервера — это осознанное решение: запись
описывает конкретную сборку. Тесты требуют: 20–300 символов на запись, никаких
слов из реализации, версии сортируются **как строки** (поэтому `0.2.31` выше
`0.2.3`), «готовится» ровно одна версия и только она без даты.

## Как устроены вещи, которые выглядят иначе, чем ожидаешь

**Карта — это растр, а не SDK.** Бэкенд отдаёт картинку 2ГИС с нарисованным
маршрутом, а приложение само кладёт поверх пины, точку «вы здесь» и подсветку
пройденного, считая координаты той же меркаторовской математикой
(`map_projection.dart`). Никакого интерактивного map SDK в проекте нет. Идея
перерисовывать дорожную геометрию самим на тайлах OSM обсуждалась и отложена.

**Один ход ИИ-чата — это два запроса к модели** (ответ, запрос инструмента,
ответ), 7–17 секунд на проде. Отсюда параметры: `ai_request_timeout_seconds` — на
**один** вызов, `ai_turn_budget_seconds` — на весь ход; если бюджет кончается на
втором вызове, отдаётся ответ от первого. У мобильного клиента отдельный таймаут
60 с на эти запросы, у остальных остаётся 20 с.

**RAG греется при входе в чат.** Первая загрузка модели эмбеддингов — 9.5 секунды
(потом 0.05), и раньше она случалась внутри первого хода, прямо в event loop,
подвешивая весь воркер. Теперь загрузка уходит в поток и запускается фоном при
создании/открытии сессии, пока человек печатает. Контекст модели ограничен
последними 12 репликами, длина диалога — `ai_chat_message_limit`, срок жизни —
`ai_chat_session_ttl_hours` (закрывается лениво при следующем заходе).

## Текущее состояние

- Версия приложения `0.2.31+22`, в истории изменений помечена как готовящаяся
  (`inProgress: true`, без даты). При выпуске — заменить флаг на дату.
- **Бэкенд не задеплоен.** Лимиты чата, прогрев RAG, бюджет хода, починка списка
  уведомлений и перестановка разделов админки ждут ручного деплоя.
- Суперпроект синхронизирован с проверенным инкрементом backend/mobile и
  текущим `tourism-platform`; внутренние рабочие планы остаются локальными.

  контекстные quick replies, однократное подтверждение controls, каталог перед
  генерацией, профиль в параметрах диалога, актуальный вопрос в RAG, исправления
  карточки и обычный iOS pop из чата к форме.
- Предпросмотр предложения: приватные `GET …/proposals/{id}/preview` и `/map`,
  `PATCH …/trip-date`. Не принимает предложение и не расходует новую квоту.
  **Перед запуском обновлённого backend нужна миграция `0055_proposal_preview`.**
- План по дням предварительный: пути, посещения, перерывы, потребность в ночлеге,
  выбор даты. Конкретные отели/кафе не подбираются; в прохождении пока прежние
  точки. План сохраняется в `Route.accessibility.trip_plan` при принятии.
- Коммиты отправлены в GitLab `origin/main`: backend `62e6074`, mobile `a5a16ea`.
  В версии `0.2.31` добавлены пользовательские записи об инкременте;
  флаг `inProgress` не снят. Переключение модели и deploy не делались.
- Собственная сборка тоже учитывает бюджет/людность: известная минимальная
  цена выше дневного бюджета в RUB исключает место; «бесплатно»/нулевой бюджет
  исключают заведомо платное. Неизвестные цены не считаются бесплатными и
  помечаются в расписании. Это пока не полная смета по дням.
- Для повторной сборки точки последних трёх предложений **этой сессии и
  пользователя** получают небольшой штраф ранжирования. Это не жёсткое
  исключение: маленький каталог не ломается, ограничения и интересы важнее.
- Backend: **556 тестов прошли** (`tests/unit` + security planning sessions и
  generate), Ruff и mypy прошли. Тесты запускались с локальными PostGIS/Redis.
  Для проверки отсутствующего ключа DeepSeek переопределять `DEEPSEEK_API_KEY=`:
  иначе одноимённый тест подхватывает реальный ключ из локального `.env`.
- Mobile: **481 тест прошёл** при `flutter test --concurrency=1`, включая
  macOS goldens; `flutter analyze` без замечаний. В параллельном прогоне один
  раз упал `image_cache_security_test` (отдельно и последовательно проходит).
  Сам кеш в этом инкременте не менялся; нестабильность параллельного теста
  не считать устранённой. Для golden чата явно прогревается `route_header.jpg`,

  Его данные сохранены, миграции не откатывались. Другие сервисы не менялись.
- Подробный статус, бизнес-ограничения расписания и план ИИ-поддержки:
  `tourism-platform/docs/ai-travel-agent-trip-plan-2026-09-08.md` (локальный документ).

Новый чат теперь живёт на `/match/chat` над формой, а не переключается внутри
корневой страницы. Не возвращать туда `AppEdgeBackGesture`: он конфликтует
с интерактивным Cupertino-жестом. Legacy `/match/resume` возвращается к истории.
Проверка реального iOS-жеста — `test/features/route_match/chat_navigation_test.dart`.

Синтетическая схема допустима только с предупреждением. `overnight_needed`
не означает наличие отеля или безопасного места ночлега. Существующий
`длительность → число точек` ещё не заменён полноценным планировщиком поездки.
